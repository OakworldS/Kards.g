# INE：独立节点编辑器

INE（Independent Node Editor）是一套用纯 GLua 写的 2D 节点编辑器框架，独立于具体玩法。
它提供画布、节点、连线、变量、序列化与多实例管理，使用方只需注册节点并消费导出的图数据。
Kards 是它的第一个使用者，用 INE 编排卡牌效果。

与 Wiremod 在世界里用实体布线不同，INE 的图完全在界面内绘制，产物是数据而不是地图里的装置。

## 设计目标

- 通用：节点类型由注册决定，编辑器本身不包含任何卡牌概念。
- 数据驱动：节点外观与控件写在 JSON 模板里，新增模板不改渲染代码。
- 双轨节点：模板节点描述静态控件，代码节点可在运行时重建端口、打开浮层、嵌入输入框。
- 编辑与执行分离：INE 只负责编辑与导出，图如何生效由使用方决定。
- 多实例：主画布可以同时打开函数子编辑器等独立面板。

## 与 Wiremod 的对比

| 维度  | Wiremod         | INE               |
| --- | --------------- | ----------------- |
| 画布  | 3D 世界内，实体之间拉线   | 2D 面板，HUDPaint 绘制 |
| 节点  | 实体，如门电路、表达式、CPU | 逻辑节点，如执行、条件、循环、事件 |
| 连线  | 世界坐标里的 Wire     | 画布上的执行线与数据线       |
| 运行时 | 电路实时运行，驱动实体     | 图保存为数据，由使用方解析执行   |
| 产物  | 地图里的装置          | 结构化数据，可随内容分发      |
| 依赖  | Wire 工具枪与相关实体   | GLua              |

两者不是替代。

## 架构

INE 横跨 Think 与 HUDPaint 两个阶段，共用一份实例状态。

| 层   | 文件                                  | 职责                        |
| --- | ----------------------------------- | ------------------------- |
| 核心  | `cl_ine_node_editor.lua`            | 实例创建、节点注册、绘制调度、序列化、公共 API |
| 绘制  | `cl_ine_node_drawing.lua` 等         | 节点体、端口、连线、选中态、缩放后的坐标换算    |
| 输入  | `cl_ine_input_handling.lua`         | 拖拽、框选、连线、平移、滚轮缩放          |
| 变量  | `cl_ine_var_op_nodes.lua`           | 代码层变量节点、端口动态重建、内联输入与浮层    |
| 函数  | `cl_ine_function_sub_editor.lua`    | 函数类变量的子编辑器，独立实例           |
| 模板  | `data_static/kards/node_templates/` | 模板节点的外观与控件描述              |

每个实例保存 `nodes`、`connections`、`dataConnections`、`variables` 与视图变换。
输入层与绘制层用帧号标志协同，避免同一次点击既被下拉框消费又被当成节点拖动；内联控件会注册交互矩形，交给输入层排除。

## 图模型

INE 的图由两类连接组成，它们互不替代。

|       | 执行线 `connections` | 数据线 `dataConnections` |
| ----- | ----------------- | --------------------- |
| 作用    | 决定接下来执行哪个节点       | 把值或引用送到另一个节点          |
| 值     | 无                 | 有，带类型                 |
| 流向    | 从输出端口到输入端口，顺序执行   | 从输出端口到输入端口，按需读取       |
| 分支    | 条件与抉择支持两个出口       | 一个输出可以接往多处            |
| 断开后   | 后续节点不再执行          | 目标节点回退到默认值或全局变量       |
| 与起点关系 | 从起点节点开始串联         | 不参与执行顺序               |

### 执行线

执行线是控制流。起点节点 `start_point` 自动创建且不可删除，其余节点由执行线串在它后面。
带 `hasSecondOutput` 的节点有两个出口，条件节点分为满足与不满足，抉择节点分为效果一与效果二。
没有接入执行线的节点不会在对局中触发。

### 数据线

数据线是数据流，也是 INE 与普通流程图最大的区别。

- 端口带类型，连线要求两端类型匹配。变量节点按类型给出不同颜色的端口，颜色与变量类型对应。
- 一个输入点可以接多条同类型数据线，例如判断节点可以同时接入多个数字来源。
- 数据线接入时，目标节点会自动创建或填充对应的设置行与比较行，不需要先手工加一行再接。
- 断开数据线时，目标节点会重置对该变量的引用，回退到全局变量或默认值。
- 变量改名后，已连接的数据线会同步更新端口名，不会留下失效引用。
- 数据线不决定执行顺序，只决定某个节点在轮到自己时读到什么。

变量操作节点是数据线的典型使用者：设置变量节点从数据线读取新值，判断变量关系节点从数据线读取左操作数。

### 端口与节点实例

节点模板定义端口数量与类型，代码节点可以在运行时重建端口，例如设置变量节点会为每一行变量生成一个输入点。
端口以 `{ id, name }` 描述，重命名时需要同步数据线里记录的变量名。

## 节点类型

Kards 注册了 15 个模板节点，位于 `data_static/kards/node_templates/`。

| 文件                      | 节点   | 作用                 |
| ----------------------- | ---- | ------------------ |
| `trigger.json`          | 触发   | 效果入口               |
| `action.json`           | 执行   | 使卡牌获得、取消或被消灭       |
| `condition.json`        | 条件   | 数量与关键字判断，双出口       |
| `loop.json`             | 循环   | 遍历与第二个出口           |
| `event_monitor.json`    | 事件监测 | 监听属性变化、指令、反制、加入、回合 |
| `register_hook.json`    | 注册钩子 | 属性修饰与事件钩子          |
| `turn.json`             | 回合   | 回合相关操作             |
| `extract.json`          | 抽取   | 从集合取项              |
| `target_selector.json`  | 目标选择 | 选择单位或玩家            |
| `choice.json`           | 抉择   | 两个效果分支             |
| `command.json`          | 指令   | 打出指令               |
| `property.json`         | 属性   | 属性读写               |
| `headquarter.json`      | 总部   | 总部相关操作             |
| `trigger_function.json` | 触发函数 | 调用函数类变量            |
| `card.json`             | 卡牌   | 卡牌引用与状态            |

除模板节点外，还有代码层注册的变量操作节点。

## 变量系统

变量分六种，标识、颜色与类型对应，见 [cl_ine_var_op_nodes.lua](../lua/card_editor/ine_editor/cl_ine_var_op_nodes.lua#L354-L361)。

| 标识  | 类型  |
| --- | --- |
| `n` | 数字  |
| `e` | 对象  |
| `g` | 数组  |
| `t` | 文本  |
| `b` | 布尔值 |
| `f` | 函数  |

> [!INPORTANT]
> 
> 当前，函数类型的参数未实际应用到战斗系统，且没有返回值。函数的嵌套尚未在内部测试

作用域分 `Battle` 与 `OffTable`，前者只在牌桌上有效，后者跨对局保留，见 [cl_ine_function_sub_editor.lua](../lua/card_editor/ine_editor/cl_ine_function_sub_editor.lua#L181-L200)。

变量操作节点不走 JSON 模板，注册在代码层。它们需要动态端口、内联输入框与浮层，模板无法表达。随着插件的开发，变量操作节点会全部启用（开发）

| 节点     | 状态      | 作用                      |
| ------ | ------- | ----------------------- |
| 设置变量   | 已启用     | 修改一个或多个变量               |
| 判断变量关系 | 已启用，仅数值 | 多条件比较，行间用与、或连接，输出一个布尔结果 |
| 新建变量   | 未启用     | 创建任意类型变量并输出引用，局部变量      |
| 转换与提取  | 未启用     | 数字取整、数组取项、文本截取等         |

函数类型可以打开子编辑器单独作图，保存后作为可复用变量参与调用，入口见 [cl_ine_function_sub_editor.lua](../lua/card_editor/ine_editor/cl_ine_function_sub_editor.lua#L31)。

## 模板与代码节点的分工

模板节点是一份 JSON，字段义如下。

| 字段                       | 说明                           |
| ------------------------ | ---------------------------- |
| `type`                   | 模板类型标识，使用方的解析器按它分派语义         |
| `color`                  | 节点标题条颜色                      |
| `hasInput` / `hasOutput` | 是否显示左右端口                     |
| `hasSecondOutput`        | 是否有第二个输出                     |
| `names`                  | 各语言的节点名                      |
| `configs`                | 各语言的配置串，描述节点内显示的控件与分支        |
| `base`                   | 以序号引用 `configs` 中的控件，描述排布与嵌套 |

配置串是一套紧凑的描述语言，文字加引号、选项组用大括号、输入槽用方括号、分支用 `if` 与 `end`。以 [action.json](../data_static/kards/node_templates/action.json) 为例，`'使'` 是前缀文字，`{获得、取消、被消灭}` 是三选一，`[]` 是数值输入，`if 造成伤害 then ... end` 决定选中后追加哪些控件。

代码节点通过 `LogNewNode` 注册，参数含类型、颜色、端口、配置串与绘制函数，见 [cl_ine_node_editor.lua](../lua/card_editor/ine_editor/cl_ine_node_editor.lua#L3160-L3190)。

> [!NOTE]
> 
> 模板节点只能显示静态控件，代码节点可以按数据动态改变自身高度与端口，适合变量、函数这类结构不固定的节点。

## 序列化

编辑器的图可以整体导出与导入，内容为节点、执行线、数据线与变量，见 [ExportNodeEditorData](../lua/card_editor/ine_editor/cl_ine_node_editor.lua#L2886) 与 [ImportNodeEditorData](../lua/card_editor/ine_editor/cl_ine_node_editor.lua#L2963)。
导入时会校验未注册的节点与不属于当前面板的节点，并给出警告。
Kards 在卡牌保存时把这个结构写进卡牌效果，因此图可以随卡牌分发，而不依赖编辑器在线。

## Kards 侧如何执行

INE 本身不执行。Kards 在效果页创建 ID 为 `card_effect_editor` 的实例，见 [cl_canvas_editor.lua](../lua/card_editor/canvas_editor/effect_editor/cl_canvas_editor.lua#L1788-L1799)，图保存后由解析器翻译。

1. 编辑器导出节点、执行线、数据线与变量
2. 图随卡牌效果保存
3. 对局中由 [sh_node_parser.lua](../lua/kards/sh_node_parser.lua#L1-L58) 按模板类型分派到语义执行器，见 [sh_node_semantics.lua](../lua/kards/sh_node_semantics.lua#L1-L31)
4. 变量写入 VarLib，钩子注册到 EngineHooks，时序记录在 TickLog
5. 服务端权威执行，客户端只负责编辑与展示



## 扩展与调试

- 注册节点：`LogNewNode(nodeParams, nodeName)`
- 新建面板：`CreateNewNodeEditor(panelID, pos, scale, allowedNodes, ...)`，支持多实例
- 热重载模板：`kards_reload_templates`，改完 JSON 不必重启
- 调试宽度计算：`kards_ine_node_debug 1`

## 现状与限制

- 处于 Alpha 阶段，通用节点仍在补齐
- 变量操作节点按测试版裁剪：新建变量、转换与提取、非数值比较尚未启用
- 没有撤销与重做，也没有复制粘贴
- 新增模板不等于可执行，执行依赖解析器侧的语义实现
- 主编辑器集中在少数文件里，`cl_ine_node_editor.lua` 过三千行，改动时注意定位
