## 2026-07-18 - 北极护航队：抽 2 单位

### 效果描述

从卡组中抽取 2 张**单位**牌入手牌。

### 现有节点能力

- Card 节点 `抽取` 分支：`[] '张' {$指定$、卡组顶、卡组底、随机}` 可以控制抽卡数量和来源
- **缺少**：按卡牌类型（单位/指令/反制）过滤抽卡的能力

### 结论

现有节点**无法实现**。

### 解决方案（规划中，待实施）

在 Card 节点的 `抽取` 分支中增加可选的类型过滤选项，使 DSL 变为：

```
if 抽取 then
    [] '张' {卡组顶、卡组底、随机、$指定$}
    if $指定$ then
        ...
        {单位、指令、反制} '类型卡牌'
    else
        '的'
        {单位、指令、反制}
        '卡牌'
    end
end
```

用户可配置为 `2 张 卡组顶 的 单位 卡牌`，语义为"从卡组顶抽取 2 张单位牌"。

**配套后端变更**：需要实现基于卡牌类型过滤的抽牌逻辑，从卡组中按类型查找并抽取指定数量的卡牌。

## 2026-07-18 - 轰炸机黑手党：开发一张美国轰炸机。若剩余指挥点≥6，对敌方单位造成2伤害

### 效果分解

1. **开发一张美国轰炸机**
2. **条件：剩余指挥点≥6**
3. **条件成立时：对敌方单位造成2伤害**

### 现有节点能力及缺口

#### 缺口①：开发搜索缺少国籍+子类型过滤

- Card 节点 `开发` 分支：`[] '次' {卡组中、卡组顶、卡组底、本国指令、本国精英指令、本国精英单位} '的牌'`
- **缺少**：按国籍（美国）和子类型（轰炸机）组合搜索的能力

#### 缺口②：条件检查缺少「指挥点」数值源

- Condition 节点可检查：单位数量、总部血量、不同国籍单位数、最大/最小攻击力/防御力单位
- **缺少**：`剩余指挥点` 作为可配置的比较数值

#### 缺口③：动作节点缺少「造成伤害」

- Action 节点现有动作：撤退、移动(到前线)、交战、战斗、加入战场、加入前线、压制、抑制、转换、修复、控制、免疫、情报
- **缺少**：`造成伤害` 或 `对...造成...伤害` 的动作

### 结论

现有节点**无法实现**，三个子效果存在三处独立缺口。

### 解决方案（规划中，待实施）

#### 方案①：扩展 Card 节点 `开发` 分支（✅ 已实施）

在 `开发` 分支中增加国籍+子类型过滤选项，使 DSL 可配置为 `1次 卡组中 美国 轰炸机 的牌`：

```
elseif 开发 then
    [] '次' {卡组中、卡组顶、卡组底、本国指令、本国精英指令、本国精英单位}
    if 卡组中 or 卡组顶 or 卡组底 then
        {@nationality}  ← 国籍选择（引用规则词汇表，支持自定义扩展）
        {单位、指令}                                              ← 新增类型选择
        if 单位 then
            {战斗机、坦克、轰炸机、炮兵、步兵}                       ← 新增子类型选择
        end
    end
    '的牌'
```

#### 方案②：Condition 节点数值源改用 `[lib+...]` 模式 （✅ 已实施）

不再硬编码预设列表，而是利用 DSL 的 `[lib+选项]` 能力，让数值源既能选预设选项，也能接入 Varlib 中的任意数字变量：

```
n'当' 
{敌方、友方} 
[lib+单位数量、总部血量、不同国籍单位数、最大攻击力单位、最小攻击力单位、最大防御力单位、最小防御力单位] 
{=、>、<、>=、<=} [lib] (n比较结果、p布尔值)
```

用户在数字槽中可切换：

- **变量库模式**：选择 Varlib 中任何数字变量（包括已新增的"剩余指挥点"）
- **预设模式**：快捷选择常用的 {单位数量、总部血量、...}

**变更内容**：在 Varlib 的 Battle 区域新增 `FriendlyCommandPoints` / `EnemyCommandPoints` 变量。

#### 方案③：改造「属性」节点为「属性与伤害」+ Action 节点增加「造成伤害」（✅ 已实施）

**改动一：属性 → 属性与伤害（`trigger.json`）**

在原有攻击/防御的基础上新增 `伤害` 选项，防御操作增加 `受到`：

```text
'使' {$} '卡牌' {攻击、防御、伤害}
if 攻击 then
{设为、增加、减少} []
end
if 防御 then
{受到、设为、增加、减少} []
end
if 受到 then
'伤害'
end
(n攻击力、n防御力)
```

**改动二：Action 节点增加「造成伤害」选项（`action.json`）**

在 Action 节点的 `获得` 分支中增加 `造成伤害`，接受伤害数值输入：

```text
if 获得 then
    {撤退、移动(到前线)、交战、战斗、加入战场、加入前线、压制、抑制、转换、修复、控制、免疫、情报、造成伤害}
    if 造成伤害 then
        '造成' [] '点伤害'
    end
end
```

**配套后端变更**：需要实现以下新逻辑：

1. 按国籍+子类型从卡组搜索卡牌的开发机制
2. 对指定单位造成定量伤害的执行逻辑

方案 B（新增节点）更清晰，避免 Condition 节点过度膨胀：

## 2026-07-18 - 海鹰：敌方卡牌造成的伤害 -1

### 效果分析

> 持续效果：所有敌方卡牌造成的伤害值 -1。

这不是一次性的动作或属性修改，而是一个需要**持续存在并生效**的全局修饰（光环/被动）。

### 现有节点能力及缺口

| 概念                     | 能否表达       |
| ---------------------- | ---------- |
| 一次性操作（抽牌、改属性、战斗等）      | ✓          |
| 条件判断（数值比较）             | ✓          |
| 事件触发（部署、回合等）           | ✓          |
| **全局持续修饰：注册一个长期生效的效果** | ✗ **完全缺失** |

### 结论

现有节点**无法实现**，且不属于任何已有方案范围。设计体系中缺少"持续修饰符"这个基本概念。

### 解决方案（规划中，待实施）

#### 核心问题：底层逻辑不能在节点处直接修改

"敌方卡牌造成的伤害 -1" 本质上是修改战斗系统的核心伤害计算逻辑。节点系统只能"执行一次性操作"和"响应已发生的事件"，无法在底层逻辑执行时插入修改。

解决方案是引入**引擎钩子系统（Engine Hook System）**：

```
战斗系统底层函数
  └→ 在关键计算点插入钩子点
      └→ 遍历所有注册的修饰钩子 → 累计偏移 → 应用到最终值
```

**钩子点位置**（需要在战斗系统代码中预设）：

| 钩子点                | 触发时机     | 可修改参数            |
| ------------------ | -------- | ---------------- |
| `OnModifyDamage`   | 计算最终伤害值时 | `{来源, 目标, 伤害量}`  |
| `OnBeforePlayCard` | 打出卡牌生效前  | `{卡牌, 玩家, 效果}`   |
| `OnModifyStat`     | 读写卡牌属性时  | `{卡牌, 属性名, 当前值}` |

**节点不直接修改底层逻辑**，而是通过节点向引擎钩子点注册修饰函数：

```
注册修饰节点:
  作用目标: {敌方、友方、所有} '卡牌'
  修饰对象: {造成的伤害、攻击力、防御力}
  修饰方式: {增加、减少、设置为} []
  作用域: {存活在场、永久}
  (p修饰ID)
```

**执行流程**：

```
1. 海鹰部署 → 注册修饰节点向引擎注册修饰
2. 引擎将修饰存入活跃修饰列表，绑定海鹰实体
3. 敌方单位造成伤害时，战斗系统进入 ApplyDamage
   └→ 触发 OnModifyDamage 钩子点
       └→ 遍历修饰列表，找到"敌方卡牌伤害 -1"修饰
       └→ 实际伤害 = 原始伤害 - 1
4. 海鹰离场 → 引擎自动注销绑定的所有修饰
```

**"100%覆盖"的关键**：修饰钩子注册在 `ApplyDamage` 函数内部，所有经过该函数的伤害都会被修饰影响，无论来源是战斗系统还是节点。

**配套后端变更**：

1. 引擎层维护"活跃修饰列表"，支持增删查
2. 战斗系统在 `ApplyDamage` 等关键函数中插入钩子点
3. 修饰与卡牌实体生命周期绑定（在场生效，离场注销）
4. 多个修饰叠加规则（加法叠加/乘法叠加）

## 2026-07-18 - 步兵第 55 团：亡计：下个友方回合开始时，获得 2 个指挥点

### 效果分解

1. **亡计触发**
2. **延迟到下个友方回合开始时**
3. **获得 2 指挥点**

### 现有节点对照

| 环节            | 节点                                 | 状态         |
| ------------- | ---------------------------------- | ---------- |
| 亡计触发          | Event Monitor → `{友方}{单位}{触发}{亡计}` | ✓          |
| 获得 2 指挥点      | Command → `{友方}{指挥点}{增加}2`         | ✓          |
| **下个友方回合开始时** | Turn → `等待 [] 回合`                  | ✗ **精度不够** |

### 缺口：Turn 节点缺少回合相位精度

Turn 节点的 `等待 [] 回合` 只能等待 N 个完整的回合周期，无法指定：

- **哪一方**的回合（友方/敌方）
- **回合的哪个阶段**（开始/结束）

"下个友方回合开始时"需要三个维度的精确组合：`{己方回合、敌方回合} × {开始时、结束时} × {第 N 个}`。Turn 节点目前全部不可指定。

### 结论

现有节点**无法实现**。新缺口，不属于已有方案。

涉及两个新概念：**注册效果到实体**（核心）和**召唤单位**动作。其中"注册效果到实体"不仅是"方面军"的需求，更是实现词条、自定义词条、自定义规则的基础机制。

#### 方案①：利用「触发函数」节点实现「注册效果到实体」

利用已存在的**函数变量**系统，新增 **触发函数** 节点。该节点允许用户从编辑器内已定义的函数变量中选择一个函数，将其注册/触发到目标实体上。

函数变量本质上封装了一个效果子图（在独立的子编辑器中编辑），通过触发函数节点，可以将该子图注册到目标实体，使其在战斗中生效。

**触发函数节点设计**：

```
类型: trigger_function
颜色: [140, 80, 200]
hasInput: true
hasOutput: true
config: e{触发一次、保持触发、停止保持触发} # '到' {$} '，效果图案' {主动效果、被动效果、无、@combat_keywords}
output: (e目标、t效果图案类型)
```

**组件说明**：

| 组件   | 语法                                       | 说明                                                                               |
| ---- | ---------------------------------------- | -------------------------------------------------------------------------------- |
| 触发模式 | `e{触发一次、保持触发、停止保持触发}`                    | 输入目标 e，选择触发模式。`触发一次`= 立即执行一次效果并结束；`保持触发`= 持续注册到目标，周期执行；`停止保持触发`= 从目标上移除之前注册的持续效果 |
| 函数槽  | `#`                                      | 选择编辑器内已定义的函数变量，该函数封装了效果子图                                                        |
| 目标选择 | `'到' {$}`                                | 选择效果注册的目标实体（卡牌、总部等）                                                              |
| 效果图案 | `'，效果图案' {主动效果、被动效果、无、@combat_keywords}` | 选择注册到实体后在实体右侧显示的效果图案类型，`@combat_keywords` 引用战斗词条词汇表，使实体自带词条也能显示对应效果图案            |

**执行逻辑**：

1. `触发一次`：在当前卡牌数据中执行该函数的子图，函数完成后效果结束。适用于一次性效果（如"部署时造成的伤害"）
2. `保持触发`：将函数引用注册到目标实体上，实体携带该函数，在战斗系统中按函数定义的条件/周期执行。例如"方面军"的效果可编写为一个函数，注册到友方总部，每回合自动执行
3. `停止保持触发`：从目标实体上移除之前注册的函数效果，停止执行

**效果图案系统**（新概念）：

- 注册到实体的效果需要在实体右侧显示对应的图案
- 图案类型可以是系统预设的（主动效果、被动效果、无），也可以引用战斗词条（`@combat_keywords`）中的关键词图案
- 例如，注册"亡计"效果到单位时，显示对应的亡计图标
- 效果图案系统后期可扩展为图标资源系统，自动匹配词条关键词

**"方面军"配置示例**：

```
通过触发函数节点实现"方面军"效果：
1. 使用函数变量定义一个"友方回合开始（总部受1伤+召唤T-34+回合末消灭T-34）"的函数
2. 触发函数节点配置：{保持触发} # 选择该函数 '到' {选择友方总部} '，效果图案' {被动效果}
3. 触发函数节点将函数注册到友方总部，每回合自动执行函数中的效果序列
```

**"注册效果到实体"的重要性**：

"注册效果到实体"是 Kards 战斗系统的核心概念，应用范围包括：

| 应用场景         | 说明                                 |
| ------------ | ---------------------------------- |
| 卡牌持续效果（如方面军） | 将效果函数注册到总部/单位，使其在整场战斗中周期生效         |
| 词条效果         | 战斗词条（亡计、闪击、守护等）的效果注册到卡牌实体，在战斗中自动触发 |
| 自定义词条        | 玩家自定义的词条通过函数变量定义，通过触发函数节点注册到实体     |
| 自定义规则        | 自定义规则需要注册的实体效果检测和处理，同样通过触发函数节点实现   |
| 效果图案显示       | 注册到实体的效果在右侧显示对应图案，战斗时玩家可直接看到卡牌生效效果 |

**收集方式**：在 `VarLib.Create` 或 `VarLib.ResetBattleVars` 中，除了上述预注册变量，还需遍历所有 Battle/Special 变量，筛选出对象类型（table 且有 `isUnit` 标记的结构）和对象组类型（table 数组），将路径和名称存入 `ObjectVarPaths`。排序方式同数字变量（按字母排序）。

#### 数据模型

```lua
-- CardData 新增字段
-- 默认为空表，表示无倍率加成
combatModifiers = {
    -- 输出倍率（该卡牌攻击目标时造成 ×N 伤害）
    outgoing = {
        { targetPath = "Battle.EnemyGroundUnits", multiplier = 2, targetName = "敌方陆军单位" },
        { targetPath = "Battle.EnemyHeadquarter", multiplier = 2, targetName = "敌方总部" },
    },
    -- 受伤倍率（该卡牌受到来自某源的伤害时 ×N）
    incoming = {
        { sourcePath = "Battle.AllSources",       multiplier = 2, sourceName = "所有来源" },
        -- 可按源类型精细配置：
        -- { sourcePath = "Battle.EnemyUnits",    multiplier = 1.5, sourceName = "敌方单位" },
    },
}
```

`targetPath`/`sourcePath` 直接引用 Varlib 中的对象/对象组路径。战斗系统在伤害判定时：

- **输出倍率**：遍历攻击者 `combatModifiers.outgoing`，若受击目标匹配 `targetPath`，应用 `multiplier`
- **受伤倍率**：遍历受击者 `combatModifiers.incoming`，若攻击来源匹配 `sourcePath`，应用 `multiplier`

外观编辑器的书签列表中新增一项：

| 书签名      | 简称 | 内容                                      |
| -------- | -- | --------------------------------------- |
| 单位伤害倍率配置 | 伤害 | 显示 Varlib 中所有对象/对象组，分"输出倍率"和"受伤倍率"两个子页签 |

**UI 布局**：

```
┌─────────────────────────────────────────┐
│  伤害倍率配置                              │  ← 标题
│  [输出倍率] [受伤倍率]                      │  ← 子页签切换
│                                          │
│  ┌─────────────────────────────────────┐ │
│  │ 父类  │ 目标                │ 倍率  │ │  ← 列表头
│  ├─────────────────────────────────────┤ │
│  │ 对象组 │ 敌方陆军单位        │ ×2  ▸│ │  ← 每行: 类型 + 名称 + 倍率编辑
│  │ 对象   │ 己方1号单位         │ ×1  ▸│ │
│  │ 对象组 │ 敌方总部            │ ×2  ▸│ │
│  │ ...    │ ...                │      │ │

- 倍率值默认为 ×1（无加成），点击弹出透明输入框编辑

**示例**：

- 亨舍尔 HS 129 的"对战陆军和总部时造成双倍伤害"：
  - 输出倍率 → 敌方陆军单位: ×2, 敌方总部: ×2

### if input/output 条件扩展

基于节点的**执行输入点 / 输出点连接的是什么**，定义后续元素的 if：

| ------------------ | --------------------------------- | ---------------------- |

- `input` / `output` 的值是**数组**，数组内为所连接的节点或开始点的**内部名称**
- `=` 右侧同样为数组
- 匹配规则：只要 `input` / `output` 的项与右侧**无序相等**（不考虑顺序），条件即通过
- **开始点必须有内部名称**（如"在场"、"打出"、"激活时"），供节点 config 引用

典型用途：反制画布中，连接"激活时"开始点的事件节点可配置 `if input={'激活时'}`，使其不能选择"友方回合"条件，防止反制在激活时误触发（变成指令）。

## Varlib 变量索引表 + \[lib+] 解析方案

### 目标

让战斗系统通过固定序号优雅地访问变量库中的任意数字变量，解决 Condition 节点等使用 `[lib+]` 模式时的变量定位问题。

### 变量索引表（IndexMap）

变量库创建完成后，建立序数对照表：

```
KARDS.VarLib.IndexMap[tableID] = { [index] = varPath, ... }
```

**创建流程**：

1. 调用 `GetNumericVarPaths()` 获取所有数字变量的路径列表（排序后）
2. 从 0 开始为每个变量分配唯一序号
3. 序号 → 变量路径的映射存入 `IndexMap[tableID]`
4. 同时在变量库中为每个变量标注其序号（如 `VarLib.Fields["Battle.Turn"].index = 0`）

**示例**（假设排序结果）：

| 序号  | 变量路径                         | 含义     |
| --- | ---------------------------- | ------ |
| 0   | Battle.Turn                  | 当前回合数  |
| 1   | Battle.FriendlyHandCount     | 友方手牌数量 |
| 2   | Battle.EnemyHandCount        | 敌方手牌数量 |
| 3   | Battle.FriendlyCommandPoints | 友方指挥点  |
| 4   | Battle.EnemyCommandPoints    | 敌方指挥点  |
| 5   | Battle.FriendlyHQHealth      | 友方总部血量 |
| ... | ...                          | ...    |

### 节点编辑器中的变量选择

节点配置了 `[lib]` 或 `[lib+N]` 的数字组件，在编辑器中展示为：

- `[lib]`：直接打开变量选择器，按序号列出所有变量供用户选择
- `[lib+N]`：下拉框中**第 0 个选项**固定为 "变量库"，选中后弹出变量选择器；其余 N 个为预设附加选项

用户选中变量后，节点保存该变量的**序号**（而非路径字符串）。

### \[lib+N] 运行时的解析规则

当数字组件配置为 `[lib+N]`（N 个预设附加选项），保存值为 S，运行时按以下规则解析：

```
Let L = #GetNumericVarPaths()  -- 变量库中该 table 的数字变量总数

If S < L then
    -- 选中了变量库中的第 S 个变量（S 就是序号）
    UseVarialbe(IndexMap[tableID][S])
Else
    -- S >= L，选中了预设附加选项
    -- lib 算作第 0 个选项，所以实际附加选项索引为 (S - L)
    UsePresetOption(S - L)
End
```

**举例**：

Condition 节点的数值源配置 `[lib+单位数量、总部血量、不同国籍单位数]`（N=3）：

- L=6（有 6 个数字变量，序号 0\~5）
- S=3 → 选中变量库中序号 3 的变量（友方指挥点）
- S=8 → S >= L（6），选中第 8-6=2 个预设选项（"不同国籍单位数"，索引 2，其中 0=单位数量, 1=总部血量）
- S=6 → 选中第 0 个预设选项（"单位数量"）

**注意**：`[lib]`（无附加选项）不存在此规则，其保存值 S 始终直接作为变量库序号。任何时候的序号都必须唯一，且每一次初始化后的序号排序结果必须相同。

## 2026-07-22 - 柴郡团：若上一回合未受到伤害，对敌方总部造成 2 伤害

### 术语澄清

| 术语       | 含义                       | 类型     |
| -------- | ------------------------ | ------ |
| **受伤**   | 防御力 < 最大防御力              | **状态** |
| **受到伤害** | 该单位被"造成伤害"或"减少防御"操作锁定为目标 | **事件** |

> "减少"等价于造成伤害，因为 `减少` 同时设置防御和最大防御（同比回退）。

### 效果分解

1. **条件检查**：该单位在上一回合是否被"受到伤害"事件命中？→ 否
2. **动作**：若条件成立 → 对敌方总部造成 2 伤害

### 现有节点能力

| 环节        | 节点                               | 状态        |
| --------- | -------------------------------- | --------- |
| 目标选择：敌方总部 | Target Selector → `{敌方}{总部}`     | ✓         |
| 造成伤害      | Action → `获得` → `造成伤害 [] '点伤害'`  | ✓         |
| 条件检查      | Condition → `判断数量` → `[lib] = 0` | ✓ 但缺少所需变量 |

### 缺口分析

此效果需要**三个层级的能力**，均不存在：

**① 缺少单位级事件追踪**（核心缺口）

Varlib 目前只有全局维度（总部血量、手牌数量等）和战斗维度（友方/敌方整体）的变量，没有"特定单位实例在本回合是否被某事件命中"的记录。

**② 缺少跨回合状态轮转**

即使有"本回合受伤害"标记，也需要在回合切换时自动保存为"上回合受伤害"标记，并重置本回合标记。节点系统没有回合相位钩子来做这件事。

**③ 缺少"事件→条件"直接通路**

Event Monitor 可以监测 `造成伤害` 事件，但监测结果不能直接写入可被 Condition 读取的 Varlib 状态标记。目前 Event Monitor 只是信息输出者（输出事件类型、目标等），不是状态修改者。

### 结论

现有节点**无法实现**。新缺口，不属于已有方案范围。

### 解决方案（规划中，待实施）

#### 核心思路：引擎级单位事件历史 + Condition 节点新增「事件历史」分支

游戏引擎自动维护每个单位的回合级事件记录，Condition 节点通过新增分支直接查询。

**引擎级维护**（游戏运行层，非节点 DSL）：

```
单位数据附加字段:
  eventHistory = {
    thisTurn = { damaged = false, attacked = false, targeted = false, destroyed = false },
    lastTurn = { damaged = false, attacked = false, targeted = false, destroyed = false },
  }

回合切换时自动轮转:
  lastTurn = thisTurn  (深拷贝)
  thisTurn = 全部复位
```

**事件触发时引擎自动设置**：

```
当该单位被"造成伤害"锁定为目标 → thisTurn.damaged = true
当该单位被"减少防御"锁定为目标 → thisTurn.damaged = true
```

**Condition 节点新增分支**：

Condition 节点的第一个选择组件新增 `事件历史` 选项：

```
{判断数量、关键字检查、事件历史}
if 事件历史 then
    '该单位' {本回合、上一回合} '是否' {受到过伤害、受到过攻击、成为过目标、被消灭过} {是、否}
end
```

**"柴郡团"配置示例**：

```
事件历史 → 该单位/上一回合/是否受到过伤害/否 → Action → 对敌方总部造成 2 伤害
```

#### 替代方案②：基础变量操作节点系统

更通用的底层方案——新增三个基础变量操作节点（写在节点系统代码层，不碰 JSON 模板），让玩家自由读写、转换变量。不仅实现柴郡团，还能支持任意创意效果。

所有三个节点均在底层系统代码中实现，不通过 JSON 模板定义。详见下一节完整设计。

#### 配套变更

1. **单位数据模型**：每个单位实例新增 `eventHistory` 字段，含 `thisTurn` / `lastTurn` 子表
2. **游戏引擎**：回合切换轮转、伤害事件触发标记
3. **Condition 节点**：新增 `事件历史` 分支，DSL 和解析支持
4. **Condition 节点运行时**：从目标单位的 `eventHistory` 读取对应字段并返回布尔值

### 方案定位

此方案与「引擎级事件历史」**可同时实现**，互为补充：

### 节点四：判断变量关系（EvaluateRelationship）

> **测试版状态：仅支持数值比较**（数字变量的 `{=、≠、>、<、≥、≤}`，右值为数字字面量 \[lib] 槽；其余类型（布尔/文本/对象/数组）比较为**正式版内容**，源码已注释保留并注明"正式版内容"）

> **后续补充**（原始提示词未定义此节点）：用于替代和扩展现有的 Condition 节点，支持多条件 + AND/OR 逻辑组合。
> 现有 Condition 节点保留不变（便捷场景），此节点提供完全的通用性。

#### 节点特性

- 一个节点可编排**多个条件行**，行之间用 AND / OR 连接
- 每个条件行：`左操作数 运算符 右操作数`
- 操作数类型自适应——运算符根据操作数类型动态决定可用选项
- 输出一个布尔值（p结果）

#### UI 布局

```
┌─ 判断变量关系 ───────────────────────────┐
│                                           │
│  条件1: [变量]  {=}  [变量/值]            │  ← 第一行
│          [AND]                            │  ← 连接符（最后一行不显示）
│  条件2: [变量]  {>}  [变量/值]            │  ← 后续行
│          [OR]                             │
│  条件3: [变量]  {包含} [变量/值]           │
│                                           │
│  [+ 添加条件]                             │  ← 新增条件行
│                                           │
│  (p结果)                                  │  
└───────────────────────────────────────────┘
```

#### 条件行组件详解

一行条件包含三个组件 + 一个连接符（非首行前方）：

```
[连接符]  [操作数A]  [运算符]  [操作数B]
```

**【操作数 A / B】**：变量选择槽

- 外貌类似设置变量节点中选择全局变量后的变量显示组件
- 点击可展开变量选择器（同设置变量节点的选择器 UI）
- 也可通过数据线输入
- 当操作数是**变量引用**时，其类型决定可用运算符列表
- 当操作数是**字面量**时（如直接输入数字），根据输入推断类型

**【运算符】**：类型自适应

| 操作数类型   | 可用运算符                         | 测试版状态   |
| ------- | ----------------------------- | ------- |
| **数字**  | `{=、≠、>、<、≥、≤}`               | ✅ 测试版可用 |
| **布尔值** | `{=、≠}`                       | 正式版再做   |
| **文本**  | `{=、≠、包含、不包含、开头为、结尾为}`        | 正式版再做   |
| **对象**  | `{=、≠、是空、非空}`                 | 正式版再做   |
| **数组**  | `{=、≠、包含、不包含、项目数=、项目数>、项目数<}` | 正式版再做   |

> 当运算符右侧需要字面量输入（如比较数字的右值、文本包含的匹配字符串），右操作数自动切换为对应类型的输入框/选择器。
> 当运算符右侧需要变量引用（如 `=`、`≠` 的对象比较、数组比较），右操作数保持变量选择槽。

**【连接符】**：行间逻辑

- 位于非首行条件的前方，可选 `{AND、OR}`
- 最后一行不显示连接符
- 所有条件从左到右评估，按连接符组合：`条件1 AND 条件2 OR 条件3` = `(条件1 AND 条件2) OR 条件3`
- 连接符的**优先级**固定为左结合（无括号），需要复杂嵌套时可通过数据线串联多个判断变量关系节点

**【+ 添加条件】**：按钮

- 点击后在末尾新增一行条件
- 新增行自动携带 AND 连接符（可在上一行的连接符位置编辑为 OR）

#### 类型自适应细节

**场景 A：操作数 B 是字面量**

```
操作数A = 数字变量（来自数据线）
运算符 = >
操作数B = 直接输入数字 [lib]  ← 自动变为数字输入模式，而非变量选择
```

**场景 B：操作数 B 是变量引用**

```
操作数A = 对象变量
运算符 = = 
操作数B = 变量选择器（仅显示对象类型的变量）  ← 过滤只显示同类型变量
```

**场景 C：操作数 A 改变类型**

当用户修改操作数 A 的选择（切换为不同类型的变量），整个条件行的运算符和操作数 B 组件的 UI 重新渲染：

```
原: [数字:A]  [>]  [数字输入]
改: [文本:A]  [包含]  [文本输入]    ← 运算符和B自动切换
```

#### 输出

- 唯一输出点：`(p结果)`，布尔值类型
- 所有条件评估完毕后，按连接符逻辑组合输出 true/false

## 2026-07-22 - Hx 权杖号（反制）：敌方打出指令时，将其反制，转换为"计划"

### 效果分解

1. **触发条件**：敌方打出指令
2. **拦截**：在指令效果生效前将其拦截
3. **替换**：将指令转换为"计划"而非让其正常生效

### 现有节点能力

| 环节             | 节点                                               | 状态         |
| -------------- | ------------------------------------------------ | ---------- |
| 检测"敌方打出指令"     | Event Monitor → `{敌方}{打出}{指令}`                   | ✓          |
| **在生效前拦截**     | ❌ 不存在                                            | ✗ **完全缺失** |
| **将指令替换为"计划"** | 这不是一个节点，而是节点组合，一张卡牌，需求是将该“指令”单个对象“转换”为一个卡牌对象“指令” | <br />     |

### 缺口分析

这是与"海鹰"**同一类缺口**：需要引擎级的事件管道钩子。

**现有架构**：Event Monitor 在事件**已发生后**通知节点图，此时指令效果已经准备执行，无法拦截。

```
敌方打出指令 → 指令效果执行 → Event Monitor 通知 → 节点图响应
                                                        ↑ 太晚了
```

**需要的架构**：在事件生效前插入拦截点。

```
敌方打出指令 → [钩子点：可拦截/替换] → 指令效果执行 → Event Monitor 通知
                     ↑
              注册在此处的钩子可以：
              1. 拦截（阻止指令生效）
              2. 替换（改为"计划"）
```

### 结论

现有节点**无法实现**。与海鹰方案同属"引擎钩子系统"的范畴。

### 解决方案（规划中，待实施）

#### 方案：引擎钩子系统 + 注册钩子节点

与海鹰共享同一套**引擎钩子系统**，在 `OnBeforePlayCard` 钩子点注册拦截钩子。

**反制画布连接约束**："激活时"开始点**只能连接两类节点**——**钩子节点**或**事件节点**（二选一）。由此开始点连接的一定是这两类节点之一，反制触发有两条路径：钩子路径（拦截型）/ 事件节点路径（响应型）。

**注册钩子节点**（海鹰方案中的"注册修饰节点"的泛化版本）：

```
节点名：注册钩子
hasInput: true       # 从开始点接入执行信号
hasOutput: false     # 无执行输出点：信号到达即注册钩子，终止执行链
config: e‘注册一个’{效果钩子、修饰钩子、替换钩子} # '到' {$} (p钩子ID)
```

- **无执行输出点**是反制可行的关键：激活时信号到达钩子节点 → 注册钩子（待命）→ 信号终止，不继续执行效果链。拦截逻辑放在 config 的函数变量中，由钩子触发时调用
- 反制效果不在激活时执行 → 反制不会变成指令

**三种钩子类型**：

| 类型       | 行为                  | 示例               |
| -------- | ------------------- | ---------------- |
| **效果钩子** | 在事件生效前被调用，可以拦截并替换事件 | Hx 权杖号：反制指令→改为计划 |
| **修饰钩子** | 在数值计算时被调用，可以偏移数值    | 海鹰：敌方伤害 -1       |
| **替换钩子** | 完全替换默认处理逻辑          | 自定义战斗规则          |

**Hx 权杖号配置（钩子路径，拦截型）**：

```
1. 画布: 激活时（开始点）→ 注册钩子(效果钩子) # 函数(反制指令并转换为计划) '到' {敌方指令}
   - 反制激活时（友方回合）信号到达 → 钩子节点注册钩子（待命）→ 信号终止
   - 敌方回合敌方打出指令 → OnBeforePlayCard 钩子点触发 → 拦截函数执行
2. 函数变量 "反制指令并转换为计划":
   输入: e卡牌、e打出者
   逻辑: 拦截 → 取消该指令的效果
         → 从模板库取出"计划"卡牌数据
         → 创建"计划"卡牌实例并加入打出者手牌
         → 返回"已拦截"
```

**"拦截"操作在节点中的表达**：

需要新增一个节点或节点分支来表达"拦截并替换"的语义。在设计上，这是对"触发函数"节点中 `{触发一次}` 模式的扩展：

```
触发函数模式新增: {触发一次、保持触发、停止保持触发}
拦截次数不设 {拦截一次、保持拦截} 选项（2026-08-04 已定，见 战斗系统规划.md 待明确点 #8）：
- 拦截次数由卡牌类型固定决定，无需玩家选择：
  - 单位 / 总部（在场持续）→ 保持拦截
  - 指令 / 反制（触发后移除）→ 拦截一次
```

拦截模式的函数变量需要额外返回一个布尔值表示"已拦截"。

**事件节点路径（响应型备选）**：

"激活时"开始点也可连接事件节点：

- 事件节点首条件通常为"敌方回合"：激活信号（友方回合）到达时条件为假，不通过 → 反制不会在激活时触发
- 敌方回合的**每一个刻度**都触发"激活时"开始点的信号（时间刻系统，见 战斗系统规划.md）→ 事件节点首条件"敌方回合"为真 → 再按具体事件条件过滤 → 匹配的刻度才通过执行效果

**防误配（`if input`** **扩展）**：若事件节点首条件被误配为"友方回合"，激活信号会直接通过 → 反制变成指令。事件节点连接"激活时"开始点时，可配置 `if input={'激活时'}` 使其不能选择"友方回合"。语法规则见上文「if input/output 条件扩展」。

**共享操作类型枚举（2026-08-04 已定）**：事件节点与钩子节点**保持分离**（响应型/拦截型），但操作类型统一由时间刻系统提供枚举，两者共同引用；钩子节点 config 增强为复用事件节点的条件树做事件过滤，过滤通过后再调用函数变量的拦截逻辑。设计决定详见 `e:/工作专用/关于 kards/战斗系统规划.md` 第 7 节。

#### 与基础变量操作节点的关系

基础变量操作节点 + 引擎钩子系统 = 完整的效果表达系统：

```
基础变量操作节点: 读写任意变量
          ↓ 配合
引擎钩子系统: 在底层逻辑中注入自定义变量操作
          ↓ 实现
任意卡牌效果: 包括柴郡团、海鹰、Hx 权杖号
```

**"计划"卡牌的说明**："计划"是一张有完整卡牌数据的**独立卡牌实体**，不是卡牌类型。
转换逻辑不是简单地改类型字段，而是：

1. 拦截敌方打出的指令卡 → 取消其效果
2. 从卡牌模板库取出"计划"卡牌数据
3. 创建"计划"卡牌实例并加入适当区域（如手牌/牌库）

这是游戏数据模型层面的操作，不是节点层面的需求。节点层面只需要表达"拦截并替换为指定的卡牌"这个语义。

## 统一槽系统（Slot System）设计

### 动机

在基础变量操作节点和其他现有节点中，存在大量具有共同行为的组件：它们要么**设置一个值**，要么**引用一个变量**。之前每个槽类型都是独立实现的，现在将全部抽象为统一槽系统。

### 槽的定义

一个"槽"（Slot）是一个 UI 组件，具有：

1. **类型标识**：一个字符 + 颜色，标识槽的值类型
2. **值区域**：显示当前值（字面量或变量名）
3. **交互行为**：点击类型标识切换模式，点击值区域打开选择器/输入器

### 槽类型一览

| 槽类型 | 字符   | 颜色           | 字面量模式      | 变量模式           |
| --- | ---- | ------------ | ---------- | -------------- |
| 数字槽 | `n`  | 黄色 `#E6C81E` | 输入数值       | 选择 Varlib 数字变量 |
| 函数槽 | `#`  | 紫色 `#B446C8` | —          | 选择函数变量         |
| 对象槽 | `o`  | 红色 `#C83C3C` | —          | 选择对象/对象组变量     |
| 文本槽 | `t`  | 绿色 `#4CAF50` | 输入文本       | 选择文本变量         |
| 布尔槽 | `b`  | 灰色 `#9E9E9E` | true/false | 选择布尔变量         |
| 数组槽 | `[]` | 橙色 `#FF9800` | —          | 选择数组变量         |
| 插图槽 | `p`  | 粉色 `#E91E63` | —          | 选择插图资源         |

### 槽的行为

**核心行为**：

```
点击类型标识 → 切换模式（仅支持两种模式的槽）
    ↓
点击值区域 → 
  字面量模式 → 展开类型对应的输入器
    ↓ 输入完成
  保存字面量值
    ↓
  变量模式 → 展开变量选择器（过滤为相同类型）
    ↓ 选择完成
  保存变量引用（路径/序号）
```

**输入器/选择器的类型适配**：

| 槽类型 | 字面量输入器          | 变量选择器         |
| --- | --------------- | ------------- |
| 数字槽 | \[lib] 数字输入     | 数字变量列表        |
| 函数槽 | —               | 函数变量列表 + 预览信息 |
| 对象槽 | —               | 对象变量列表（含分组）   |
| 文本槽 | 文本输入框（可切换至变量引用） | 文本变量列表        |
| 布尔槽 | true/false 单选   | 布尔变量列表        |
| 数组槽 | —               | 数组变量列表        |
| 插图槽 | —               | 插图资源预览列表      |

**数据线接入**（仅支持变量模式的槽）：

```
数据线接入 → 自动切换为变量模式 → 显示传入变量名
数据线断开 → 恢复为之前的模式
```

### 涉及改造的现有组件

以下现有组件应重构为统一槽系统：

| 现有组件                      | 所在节点/文件                | 改为统一槽      |
| ------------------------- | ---------------------- | ---------- |
| `[]` 数字输入（带下拉框）           | 各 JSON 模板解析后的渲染        | 数字槽        |
| `[lib]` / `[lib+N]` 变量库模式 | 同上                     | 数字槽（变量模式）  |
| `#` 函数槽                   | trigger\_function.json | 函数槽        |
| `{$}` 对象选择                | 各 JSON 模板              | 对象槽        |
| 变量选择器展开后各选项               | 各 JSON 模板渲染            | 对象槽的子选择器   |
| 文本输入框（绿色 t 字符）            | 设置变量节点（规划中）            | 文本槽        |
| 插图选择（粉色 p 字符）             | 设置变量节点（规划中）            | 插图槽        |
| 下拉框描边系统                   | 数字黄、对象红、函数紫            | 统一从槽类型映射颜色 |

```
